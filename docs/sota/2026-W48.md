# SOTA digest — 2026-W48

_Swept 2026-11-28 (UTC). Window: 2026-11-21 to 2026-11-28, the days after the W47 sweep._

## Bottom line

Claude Code shipped v2.1.331 (Nov 23) and v2.1.332 (Nov 25), and the installed 2.1.332 has both. Skills over MCP reached public beta (Nov 24), but it does not load in `claude -p` or in `claude remote-control` server mode, the two ways this toolkit runs sessions. No advisory appeared after Oct 26. No recommendation this week.

## What moved

### 1. Agent CLIs and coding harnesses

- **Claude Code v2.1.331 (Nov 23) and v2.1.332 (Nov 25).** `claude --version` in the job sandbox prints 2.1.332. Each repo-relevant line, checked against the worktree: <https://github.com/anthropics/claude-code/releases/tag/v2.1.331>, <https://github.com/anthropics/claude-code/releases/tag/v2.1.332>, <https://code.claude.com/docs/en/changelog>
  - **Skills from MCP servers (v2.1.332).** "Added skills from MCP servers (beta). They show as `server:skill` in the `/` menu". Section 3 has the check.
  - **New `PreSkillShellCommand` hook event (v2.1.332).** It runs before a skill's injected command (`` !`cmd` ``). The hooks page says "PreToolUse hooks don't fire for injected commands", so `claude/hooks/deny-push-force-cluster.sh` never sees one. That leaves no gap. `git push` has no allow rule in `claude/settings.json`, and "In auto mode, a command that would otherwise need approval doesn't run while the skill loads". A later Bash call fires `PreToolUse` and the hook. No skill in `skills/`, `vendor/skills/` or the RunPod and Vast.ai plugin cache holds an injected command. <https://code.claude.com/docs/en/hooks>
  - **Mid-turn messages (v2.1.332).** "Changed SDK and `claude -p` mid-turn messages to count as the user's where feature flags aren't fetched … mark relayed text `isSynthetic: true`". The job steer FIFO (`claude/vibe-job.sh:6`) carries only text from `vibe queue steer` (`bin/vibe:1722`), which the human sends from the CLI or the page. No mark needed.
  - **Managed marketplaces auto-update, on or after Nov 30 (v2.1.331).** "plugin marketplaces in managed `extraKnownMarketplaces` will auto-update by default". The baseline is user settings, not managed. The settings reference gives third-party marketplaces `autoUpdate: false` by default, and `claude/settings.json:418,425` pins RunPod and Vast.ai by `ref`. No impact. <https://code.claude.com/docs/en/settings-reference>
  - **Rules skipped at start (v2.1.332).** `/permissions` now refuses "a rule that would be skipped at the next start, such as `rm -rf` with no tool name". A `jq` pass over both settings files finds that every rule names a tool or an MCP server. Nothing is skipped.
  - **Fixes that touch the toolkit, all installed.** A freeze when "a permission rule or hook condition with several wildcards was checked against a long command"; the `cmd* --flag*` deny rules have several. CLAUDE.md "sent to the model a second time" after a session moves into a worktree under `.claude/worktrees`. A freeze while "a hook prints output without end".
  - **W47 watch item stays open.** Neither release removes the auto-mode classifier fallback that v2.1.327 announced.
- **Codex CLI 0.172.0** (Nov 24). `codex exec resume` restores saved sandbox permissions, stdio MCP servers start on their first tool call, and an approval reviewer can be set per connected-app tool. Nothing to adopt; `codex/` holds no config. <https://learn.chatgpt.com/docs/changelog>
- **OpenHands v1.44.0 to v1.46.0** (Nov 23 to 25). Sharing and automation visibility. Nothing on sandboxing, skills or hooks. <https://github.com/All-Hands-AI/OpenHands/releases>
- **Gemini CLI, Cursor, Aider.** Gemini CLI has no release after v0.64.0 (Oct 13). The newest Cursor entry is Nov 6. The Aider history has no dates. <https://www.geminicli.com/docs/changelogs>, <https://cursor.com/changelog>, <https://aider.chat/HISTORY.html>

### 3. Protocol and ecosystem

- **Skills over MCP, public beta (Nov 24).** An MCP server can ship skills beside its tools, and they "update with the server". Tasks and Elicitation are now GA. <https://claude.com/resources/articles/skills-over-mcp-tasks-and-more>
  - The MCP docs list `claude -p` and "`claude remote-control` server mode" as sessions that do not support MCP skills. Jobs run `claude -p` (`claude/vibe-job.sh:18`). The phone sessions run `claude remote-control --spawn worktree` (`claude/systemd/claude-rc@.service:19`). Neither loads an MCP skill. <https://code.claude.com/docs/en/mcp>
  - Only an interactive terminal session on Pro, Max or Ultra loads one. There, the baseline enables `wandb@toolkit`, a remote server at `mcp.withwandb.com` (`claude/marketplace/wandb/.mcp.json`). In auto mode "The classifier decides whether the skill loads, without reading it", and "Servers can change skills at any time".
  - A search finds W&B skills only as a separate repo (`wandb/skills`), not served over MCP. Watch item: if `/skills` lists a `plugin_wandb_wandb:` skill, add the deny rule `Skill(mcp__plugin_wandb_wandb__*)` to `claude/settings.json`, the form the docs give for one server.
- **MCP turns two (Nov 24).** The post repeats the plan for the next spec in March 2027 (W46). It announces no new extension. <https://blog.modelcontextprotocol.io/posts/mcp-turns-two/>
- **Agent Skills and AAIF.** Nothing in the window. The spec page shows no date, and the newest AAIF posts are dated Oct 22. <https://agentskills.io/specification>, <https://aaif.io/blog>
