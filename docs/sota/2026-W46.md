## Bottom line

Claude Code shipped seven releases (v2.1.317 to v2.1.325, Nov 3 to 13), and no advisory appeared after Oct 26. One change reaches the toolkit: v2.1.325 makes sandboxed Bash commands follow the normal permission flow by default, and neither settings file pins the old behavior. One recommendation: pin it.

## Recommendations

One.

### 1. Pin `sandbox.autoAllowBashIfSandboxed` in both settings files

Goal: sandboxed Bash commands keep running without a prompt in vibe jobs and in remote sessions, whatever the Claude Code default is.

- Gap: v2.1.325 reverses the default (see What moved). Neither `claude/settings.json` nor `claude/vibe-job-settings.json` sets the key, and no other file in the repo mentions it.
- Effect if the release is right: jobs run `--permission-mode auto --permission-prompts none`, so a sandboxed command without an allow rule goes to the auto-mode classifier or is denied. Remote sessions (`defaultMode: auto`, 117 allow rules) prompt on the phone for the same commands.
- Timing: the installed version is 2.1.322, so the change lands with the next update.
- Change: add `"autoAllowBashIfSandboxed": true` to the `sandbox` object in both files. It keeps today's behavior and grants nothing new.
- Touchpoint: `install.sh` merges the baseline into the live file and the baseline wins, so the next install sets it (`CLAUDE.md`, "The file that is merged").
- Risk: the docs say `true` is the default, so the pin may be a no-op today. It costs two lines and protects against the doc being the stale side.

**Done when:** `jq -e '.sandbox.autoAllowBashIfSandboxed == true' claude/settings.json claude/vibe-job-settings.json` prints `true` twice, and `bats tests/` passes with one test that fails when either file drops the key.

**Source:** <https://github.com/anthropics/claude-code/releases/tag/v2.1.325> (the two `autoAllowBashIfSandboxed` lines), <https://code.claude.com/docs/en/changelog>, <https://code.claude.com/docs/en/sandboxing> (the opposing default).

**Not already covered because:** `PROJECT_STATUS.md` (2026-10-26, "unattended jobs") and the roadmap item "Prove the job write fence" cover what the sandbox and the file-tool fence block. No item or decision says whether sandboxed commands prompt.
