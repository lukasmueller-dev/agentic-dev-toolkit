## Bottom line

### 1. Fence unattended file tools to the worktree and the job dir

Goal: in a queue job, Write, Edit and NotebookEdit refuse any path outside the job's worktree and its job dir, by rule in every permission mode, not by the auto-mode classifier.

- Gap: the sandbox "covers shell commands only"; "Read, Edit, Write … follow permission rules instead". Jobs run `--permission-mode auto --permission-prompts none` (`claude/vibe-job.sh:17`, `claude/vibe-review.sh:17`). `claude/vibe-job-settings.json` fences Bash and nothing else. `docs/vibe-queue.md` does not mention file tools.
- Change: add `"permissions": { "blockWritesOutsideWorkingDirectories": true }` to `claude/vibe-job-settings.json` (the file already has a `permissions` block).
- Touchpoint: the job dir (`$VIBE_JOB_DIR`, under `~/.local/state/vibe/queue`) is outside the worktree. Both runners pass `--add-dir "$VIBE_JOB_DIR"`, or the Write tool fails on `result` and `report.md`. Bash writes keep their `sandbox.filesystem.allowWrite` list; they are unaffected.
- Risk: the settings reference does not list the key yet; v2.1.314 release notes are the only source. Check the behaviour in a smoke job before the merge.

**Done when:** `jq -e '.permissions.blockWritesOutsideWorkingDirectories' claude/vibe-job-settings.json` prints `true`; `bats tests/vibe-queue.bats` passes with a test that both runners get `--add-dir`; one smoke job that tries a Write outside its worktree and job dir is refused, and the same job's `result` and `report.md` still land.

**Source:** <https://code.claude.com/docs/en/changelog> (v2.1.314), <https://code.claude.com/docs/en/sandboxing> ("The sandbox covers shell commands only").

**Not already covered because:** `PROJECT_STATUS.md` (2026-10-26, "unattended jobs") and `docs/vibe-queue.md:21,140` fence Bash (`failIfUnavailable`, no unsandboxed retry), which the first sweep recorded. File tools sit outside that sandbox, and no roadmap item names them.
