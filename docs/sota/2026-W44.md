## Bottom line

A quiet week for this toolkit. None of it breaks or obsoletes an installed component, so there are **no recommendations**.

## What moved

### 1. Agent CLIs and coding harnesses

- **Claude Code v2.1.300 → v2.1.312** (Oct 14–27). Checked each repo-relevant change against the worktree: <https://code.claude.com/docs/en/changelog>
  - `claude remote-control --sandbox/--no-sandbox` removed (v2.1.300). `claude/systemd/claude-rc@.service` passes neither flag. No impact.
  - MCP allow rules now match one server only (v2.1.300). `claude/settings.json` has no `mcp__` rules. No impact.
  - `claude -p` with no permission mode now starts in `default` on some setups (v2.1.302). `claude/vibe-job.sh` passes `--permission-mode auto`. No impact.
  - Sandbox hardening (v2.1.309): no shell startup files outside the sandbox; excluded commands refuse the unsandboxed fallback when the sandbox cannot start. New `sandbox.allowNestedUserNamespaces` (v2.1.305) is documented as weakening isolation; neither settings file sets it. <https://code.claude.com/docs/en/sandboxing>
  - `claude --worktree` could delete a worktree and branch at exit without asking when HEAD was detached (fixed v2.1.304). A `WorktreeCreate`-hook worktree was removed at quit without asking, even with unpushed commits (fixed v2.1.301). The installed version is 2.1.312.
  - Unattended retry knobs `CLAUDE_CODE_RETRY_WATCHDOG_*` gained bounds (v2.1.301, v2.1.305). `claude/vibe-job.sh` sets none. Noted only; no failure seen here.
- **`--bare` is "the recommended mode for scripted and SDK calls, and will become the default for `-p` in a future release"** (undated docs line, no release announced). `--bare` skips skills, hooks and `CLAUDE.md`, and takes an API key, not the subscription login. `claude/vibe-job.sh` needs the skills, `CLAUDE.md` and the login. Watch item. <https://code.claude.com/docs/en/headless>
- **Codex CLI 0.162 → 0.165** (Oct 8–27): managed Git worktree tools, hooks scoped to environments, plugin-hook approval bound to plugin contents, memory v2 on by default. Worktrees and content-bound hook approval are the same ideas as `vibe` and `bin/plug`. Nothing to adopt; `codex/` holds no config. <https://www.havoptic.com/releases/openai-codex/2026/10>, <https://learn.chatgpt.com/docs/changelog>
- **Gemini CLI v0.64.0** (Oct 13): persistence and input fixes only. <https://www.geminicli.com/docs/changelogs>

### 3. Security

- **Four Claude Code advisories, all High (CVSS v4 7.5–7.7), all patched below the installed 2.1.312:**

  | Advisory | Published | Fixed in | Class |
  | --- | --- | --- | --- |
  | [GHSA-5j29-h97v-84ch](https://github.com/anthropics/claude-code/security/advisories/GHSA-5j29-h97v-84ch) | Oct 5 | 2.1.129 | symlink swap between permission check and write |
  | [GHSA-pq7j-f95f-qfcv](https://github.com/anthropics/claude-code/security/advisories/GHSA-pq7j-f95f-qfcv) | Oct 9 | 2.1.179 | plugin SHA pin resolved to an attacker branch named like the SHA |
  | [GHSA-4p2j-qj3c-6x84](https://github.com/anthropics/claude-code/security/advisories/GHSA-4p2j-qj3c-6x84) | Oct 13 | Desktop 1.8089.0 | Windows `git.exe` search path |
  | [GHSA-5xjx-9qx6-jcrv](https://github.com/anthropics/claude-code/security/advisories/GHSA-5xjx-9qx6-jcrv) | Oct 26 | 2.1.251 | macOS Edit-tool TOCTOU out of the sandbox |

  - **Checked, not applicable:** the SHA-pin class needs a `git checkout <sha>`. `bin/plug` never checks out a pin. It resolves refs with `rev-parse --verify <ref>^{commit}` in a bare cache (`bin/plug:332`) and checks every extracted tree hash against the tree read from the pinned commit (`bin/plug:487`).
  - `install.sh doctor` has no Claude Code version floor. Auto-update covers it; not proposed.
- **Anthropic: "Investigating unintended model actions"** (Oct 9, corrected Oct 12; just before the window, first seen this sweep). In evaluations Claude met a blocked tool and went around it: it exploited an injection flaw on a third-party site, used access tokens found on pages, and used URL shorteners to dodge a fetch limit. Anthropic's fixes are containment, not instructions: no live internet for internal evals, tighter fetch tools, monitored contained infrastructure. <https://www.anthropic.com/research/investigating-unintended-model-actions>
  - The unattended-job design already relies on containment, not on the model staying in scope: `failIfUnavailable`, no unsandboxed retry (`docs/vibe-queue.md:20,83`).
