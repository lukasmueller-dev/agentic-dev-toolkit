## Bottom line

## What moved

### 1. Agent CLIs and coding harnesses

- **Claude Code v2.1.326 to v2.1.330** (Nov 16, 17, 19, 19, 20). `claude --version` in the job sandbox prints 2.1.330, the newest release, so every fix below is installed. The W46 rule "reopen the version floor if the version is below 2.1.325" does not fire. <https://code.claude.com/docs/en/changelog>, <https://github.com/anthropics/claude-code/releases>
  - **The W46 pin holds.** v2.1.326: "Changed the Bash sandbox to ask before some lines that set environment variables when auto-allow is off; unattended runs can refuse them". Both baselines set `autoAllowBashIfSandboxed: true` (`claude/settings.json:334`, `claude/vibe-job-settings.json:26`), and `tests/install.bats:684` checks it. Jobs are not affected.
  - **Home-folder writes (v2.1.326).** "Changed sandboxed commands on macOS, Linux and WSL to no longer write to some sensitive home folders by default; some can be allowed with `sandbox.filesystem.allowWrite`". The job baseline allows `~/.cache/huggingface`, `~/.cache/pip` and `~/.cache/uv`. In the 40 newest job dirs, the four failed or blocked results name a USD gate and Slurm waits, not a refused write.
  - **Worktree data loss, fixed (v2.1.327, v2.1.330).** "Remote Control: Fixed stopping the server in worktree mode deleting a running session's git-ignored files, such as `.env`". v2.1.330: "Fixed `ExitWorktree` and the worktree exit dialog deleting a worktree that another running Claude Code session was working in". The remote servers run in worktree mode (`docs/remote-sessions.md:4`). The installed version has both fixes. No action.
  - **Auto-mode fallback, announced.** v2.1.327: "Changed auto mode's notice about falling back to billed classifier requests to say that an upcoming release removes the fallback; each action it would have checked will be asked about or denied". Jobs run `--permission-mode auto --permission-prompts none` (`claude/vibe-job.sh:19`), so "asked" becomes "denied". The docs do not say which accounts reach the fallback. The queue logs I read show no classifier notice. Watch item: reopen when the release lands, or when a job reports a denied action it needs.
  - **Hooks.** v2.1.327: a hook's `"decision": "block"` "hold[s] in more cases, so a hook that always prints one may start blocking calls". The one deny hook (`claude/hooks/deny-push-force-cluster.sh`) prints a decision only on a match. v2.1.328 changes how a PermissionRequest hook rewrites a command. The repo has no such hook. No impact.
  - **Sandbox start failure (v2.1.328).** Without `sandbox.failIfUnavailable`, "the next sandboxed Bash command is refused and says that the sandbox is off for the session". Jobs set `failIfUnavailable`. The remote-session baseline does not, and it now refuses instead of running a command. No change.
  - **Linux sockets (v2.1.329).** `/sandbox` now says `allowUnixSockets` entries do not open sockets on Linux. Neither settings file sets the key.
  - **No impact.** `/loop` and scheduled tasks run up to 30 days (v2.1.330). The repo schedules jobs with a systemd timer. `--add-dir` handling changed for relative paths (v2.1.326, v2.1.327). The runners pass an absolute `$VIBE_JOB_DIR`.
- **Codex CLI 0.169.1 to 0.171.0** (Nov 17 to 20). Linux seccomp rules for x32 syscalls, MCP OAuth credential fixes, sandbox permissions kept in child threads. Nothing to adopt; `codex/` holds no config. <https://learn.chatgpt.com/docs/changelog>
- **OpenHands v1.41.0 to v1.43.0** (Nov 16 to 20). Workspace and user hooks named in a dialog, an MCP OAuth callback fix, webhook source validation restored. Nothing to adopt. <https://github.com/All-Hands-AI/OpenHands/releases>
- **Gemini CLI, Cursor, Aider.** Gemini CLI has no release after v0.64.0 (Oct 13). The newest Cursor entry is Nov 6. The Aider history has no dates. <https://www.geminicli.com/docs/changelogs>, <https://cursor.com/changelog>, <https://aider.chat/HISTORY.html>

### 4. Practice

- **"External sandboxes for coding agents"** (Nov 17). The agent runs outside the sandbox and sends code to it. The sandbox servers hold an HTTP(S) allow-list proxy that swaps in credentials, so the agent never sees the secret. Here, jobs run the agent inside the sandbox, and keys sit in `~/.config/vibe/secrets.env` (`PROJECT_STATUS.md`, 2026-11-19). A credential proxy adds a component with no leak behind it. Not proposed. <https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/>, <https://blog.primeradiant.com/external-sandboxes-for-coding-agents/> (original, not fetched)
